# Operation evidence

For an admitted fixture, record the scenario ID, reset identity, supplied tool
versions, bounded starting observations, intended result, action/result IDs and
final authoritative observation. Separate expectation from what actually ran.

Use explicit failure classes: missing capability, missing intent, permission
denied, stale state, execution failure, incorrect advice, budget exhausted,
interrupted or product defect. A product defect can suggest a separate source
task but does not enlarge this exercise's write grant. Keep raw evidence in the
private run; only sanitized counterexamples and stable evidence IDs may travel
with a knowledge candidate.
