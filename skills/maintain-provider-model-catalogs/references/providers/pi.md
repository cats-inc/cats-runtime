# Pi

Keep the selected provider attached to each model. A picker row such as
`model-id [provider-id]` has three separate representations: its visible label,
Cats' `provider-id/model-id` selection, and separate CLI provider/model arguments.
Preserve an operator-requested bracketed provider suffix; it can distinguish
subscription routing from another provider offering the same model.

## Evidence and execution

Use a sufficient supplied shortlist without running `--list-models` again. For a
missing execution mapping, follow the installed Pi shim to package metadata and
read the bounded unbundled CLI parser/main module. They can establish version,
`--thinking` tokens and precedence without launching sessions or loading account
state. Global parser choices do not establish per-model menus or defaults.

The approved procedure and evidence are in
`docs/research/2026-09-23-pi-shortlist.md`. Fixed thinking belongs to internal
execution defaults, resolved by the Pi adapter for structured and plain-string
selections. Test new and resumed RPC launches, raw provider/model arguments,
custom-string preservation, and absence of editable effort/default markers.
Do not pass the bracketed display label as a model token.


## Schema-2 execution data

Retain `[openai-codex]` in `label` when requested. Use qualified Cats `id`, bare `execution.model`, explicit `execution.provider`, and fixed `pi.thinking`. Never send the display suffix to the CLI or derive a provider from a model family.

Apply the [shared data workflow](../catalog-surfaces.md) and [local patch workflow](../local-soft-patch.md).
Ordinary refreshes edit the authorized factory/override scope, evidence and generated JSON only.
There are no independent Runtime, Playground or Desktop model tables to update. Existing generic
bindings require no repeated implementation authorization; a new unsupported binding is a separate
code change. Validate labels, ordered values, defaults, custom input, and actual emitted bindings.
Discovery tests must explicitly use a `selection_mode: discovery` scope before constructing the
service. `catalogs: []` inherits factory; `models: []` empties a full/shortlist scope.
